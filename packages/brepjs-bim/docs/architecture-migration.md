# BIM architecture migration and acceptance

**Status**: Proposed implementation sequence
**Date**: 2026-09-10

This companion note orders the work governed by [ADR-0001](adr/0001-independent-product-representation-and-placement.md) through [ADR-0008](adr/0008-explicit-bim-type-identity.md). The [BIM glossary](../CONTEXT.md) governs vocabulary; the [evidence note](architecture-evidence.md) separates resolved defects, remaining limitations, reported results, and analytical examples. The ADRs define decisions. This note keeps their integration checks together without expanding them into implementation tickets.

## Acceptance scenarios

The central criterion in [ADR-0001](adr/0001-independent-product-representation-and-placement.md) is that adding a class of physical element using an existing representation requires no changes to shared geometry ownership, disposal, Placement, or aggregate measurement. Review the extension diff as well as its runtime results.

Legitimate class-specific changes remain: classification and payload/role validation, legal representation/relationship combinations, optional convenience authoring commands, shape-generating recipes, opening/filling restrictions, IFC entity/schema/predefined-type and reusable-type mappings, applicable quantities/property sets, standards-specific projections, documentation, and focused tests. Registering an IFC class in a complete semantic handler map is expected. Re-registering it in geometry lifecycle lists is a failed architecture probe.

| Scenario                                                                           | Required observable outcome                                                                                                                                                                                                                                                                                                                                                                    |
| ---------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| IfcSign and direct IfcMember using `BODY`                                          | Typed export/import preserves classification, role, metadata, type association, material, item count, World shape, and identity. One and many items work under at least two facility kinds. Neither feature edits shared lifecycle/placement/measurement. Generated curtain-wall members remain composite constituents rather than duplicate direct Members.                                   |
| Shaped typed roof with an opening                                                  | Direct Roof creation works without a rectangular roof recipe. Native and reloaded IFC shape retain outline, opening, volume, World bounds, and physical element identity. No silent proxy fallback or duplicate opening subtraction. Use a self-contained shaped-roof fixture with an opening to reproduce the reported failure.                                                               |
| Disconnected or overlapping items                                                  | Preserve item order/count through ownership and IFC round-trip. Multi-item `PARAMETRIC` and singleton `AUTHORITATIVE` are valid. Material volume uses occupied union; the analytical coincidence example receives a native test. A failed union produces unavailable measurement without modifying items.                                                                                      |
| Nested rotated Site/Facility/Part and pitched physical element with internal Datum | Authored, document-queried, and imported World geometry agree. Test both transform orders, non-origin pivots, translated/rotated internal Datum, missing parent, and cycles. Container-local results are never compared as World results.                                                                                                                                                      |
| Thin sloping panel with a hole placed far from the model origin                    | Mesh geometry in the physical element's local frame, encode placement separately, and compare reloaded closed geometry, volume, bounds, and sampled surfaces. Reported third-party corrections were below a 1 μm limit. Use that as historical context, not a universal tolerance or a snapping requirement. Qualify uncorrected upstream output and document any representation error budget. |
| Adoption/transform failure on a later item                                         | Caller inputs and the prior document state remain live and unchanged on failed transfer. Release only newly owned intermediates, exactly once. Test duplicate handles, target-document aliases, mutable collection aliases, invalid/disposed handles, returned errors, and throws.                                                                                                             |
| Partial import/export failure                                                      | Retain successful imported siblings with per-item diagnostics; withhold whole-Body aggregates for partial reconstruction. Fatal import disposes accumulated ownership. Export item failure yields no successful partial artifact and closes owned runtime resources; source Bodies stay live.                                                                                                  |
| Generated flights, curtain-wall composite, and Bodyless assembly                   | All geometry-bearing variants share placement/measurement behavior and expose every emitted style target. `NONE` is intentional. Decomposition, child placement, and constituent import do not duplicate geometry or ownership.                                                                                                                                                                |

Run these additional Placement scenarios through the public document/authoring interfaces, not only frame-algebra helpers:

| Scenario                                | Required observable outcome                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| --------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Frame queries with and without geometry | Use the same operation for a physical element, spatial container, and `NONE` assembly under translated and rotated ancestors. Own-local returns identity; World composes the full chain; a named target in another branch returns `inverse(WorldTargetFrame) × WorldSourceFrame`. Results identify both frames. No query realizes or allocates geometry. Missing source/target records, foreign-document identities, invalid chains, and unsupported reference resolution return typed errors, including for own-local queries.               |
| Moving a placement parent               | Change a parent's `LOCAL_FRAME` through the public command. Its placement descendants retain their local definitions and acquire the expected new World frames. A record related only by containment or decomposition does not move. Body-local items, Datum, identity, metadata, and unrelated relationships remain unchanged. Fresh queries reflect the commit; previously returned frame snapshots do not change.                                                                                                                          |
| Reparenting with explicit preservation  | Reparent the same nested fixture between translated and rotated parents using each required policy. `KEEP_LOCAL` retains the moved record's local pose and changes its World pose as composed; `KEEP_WORLD` retains its World pose and recomputes its local pose. Descendants with resolvable `LOCAL_FRAME` chains follow the move or retain World poses respectively, without changing their definitions. Test physical elements, containers, and bodyless assemblies. Omitted policy fails; containment and decomposition remain unchanged. |
| Rejected Placement changes              | Attempt a missing or foreign-document parent, a cycle through a descendant, an invalid rigid frame, an illegal parent relationship, and a move/reparent of a reference-based placement. Also try `KEEP_WORLD` with an unresolved ancestor. Each failure leaves graph, Placement definitions, geometry ownership, and prior query results unchanged; reference intent survives. No query observes a partially changed parent/pose pair.                                                                                                        |
| Deleting a referenced parent            | Separately exercise dependants through placement parenting, authored Placement references, containment, and decomposition. Deletion returns a typed error identifying dependants and leaves the document unchanged. Explicitly resolve those dependencies, then delete successfully. Surviving records keep their definitions and geometry; removal adds no hidden cascade, detach, or reparent. Release only the deleted record's owned geometry under ADR-0003, and subsequent lookup of its identity fails.                                |

### IFC semantic preservation and qualification

These cases implement [ADR-0006](adr/0006-ifc-exchange-adapter.md), [ADR-0007](adr/0007-ifc-import-fidelity-and-item-outcomes.md), and [ADR-0008](adr/0008-explicit-bim-type-identity.md). The acceptance path is authored document → IFC → imported-document read contract for the declared supported subset. It does not require arbitrary source IFC re-export, imported-to-authored normalization, or recovery of editable Family generators. An independent reader must verify the emitted semantic graph as well as the public import result. Entity counts and effective property values alone cannot prove retention.

| Scenario                                                                | Required observable outcome                                                                                                                                                                                                                                                                  |
| ----------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| One Family definition, 100 physical elements, two explicit BIM types    | Preserve all stable physical element identities, exactly two explicit type identities, and every membership. Shared properties and occurrence overrides remain separately inspectable after export and import.                                                                               |
| Different type keys with identical geometry                             | Both definitions and their memberships survive. Changing geometry alone does not merge or redefine types. Conflicting reuse of a definition key fails before mutation.                                                                                                                       |
| Untyped physical elements                                               | Export remains untyped where the profile permits. A profile requiring types rejects missing definitions unless an explicit supported synthetic policy is selected. Any synthetic grouping is reported and never merges authored or imported types.                                           |
| Multiple external classifications on types and elements                 | Preserve every supported association, its scope, supplied system/reference URIs and parent chain. References using the same system name and code in different editions remain distinct. Missing optional fields remain absent; an IDS requirement can make their absence a delivery failure. |
| Invalid enums, incompatible class/type pairs, and illegal relationships | Document commands reject illegal neutral graphs atomically. Required export checks reject unsupported mappings. Independently validate deliberately malformed IFC fixtures to prove the external checks detect violations that permissive parsing can miss.                                  |
| Placement parenting differs from containment and decomposition          | Preserve each relationship independently and retain the expected World frames. Aggregation and ordered nesting remain distinguishable; serialization does not drop invalid endpoints or invent placement edges.                                                                              |
| Failed geometry with retained semantic data                             | Source identity, supported type membership, property scopes, classifications, and relationships remain inspectable. Geometry failure does not erase semantics; unsupported semantic data has explicit outcomes and is not counted as preserved.                                              |
| Missing validation or unchanged counts despite changed meaning          | Changing a classification, type membership, or property must fail semantic comparison even if entity counts match. Failed, unavailable, or unrun required checks prevent qualification. A successful internal re-open cannot override that result.                                           |

CI generates new bytes from the candidate implementation for each claimed schema/profile and runs independent STEP syntax, EXPRESS, applicable normative rules, project IDS requirements, semantic comparisons, and geometry checks. Assert the expected subject coverage so an empty model or zero reconstructed products cannot pass accidentally. Keep geometry tolerances and all-item checks from the existing scenarios. Use [VALIDATION.md](../VALIDATION.md#proposed-exchange-qualification) for the matrix, commands, tool versions, and qualification receipt.

## Migration order

These are architectural outcomes, not implementation tickets or an accepted ticket sequence. Each step preserves existing public regression behavior until its documented breaking cutover. Implementation starts from a freshly identified upstream baseline, not by treating the older local checkout as current upstream.

1. **Neutral placement and Body foundation.** Move frame validation/algebra below adapters; establish explicit coordinate-space contracts, independent authority, provenance, and item count; adoption; and shared material measurement. Gate on transactional later-item failures and singleton/disconnected/overlapping Bodies. Preserve #2286/#2295 tests and investigate the analytical counterexample. Do not implement grid/alignment solvers. Related decisions: [ADR-0003](adr/0003-geometry-ownership-and-material-operations.md), [ADR-0004](adr/0004-document-resolved-placement-and-datum.md), [ADR-0002](adr/0002-authored-body-authority.md).
2. **Representation convergence.** Move every stored-solid class onto Body ownership, including Roof, Proxy, and Earthworks Fill. Add explicit generated/composite/absent variants. Gate on exhaustive dispatch and the absence of lists keyed by class in shared lifetime, transform, and measurement operations. Related decisions: [ADR-0001](adr/0001-independent-product-representation-and-placement.md), [ADR-0003](adr/0003-geometry-ownership-and-material-operations.md).
3. **Document and authoring cutover.** Move recipe generation out of the document; provide direct authored-Body creation and document-owned parent-chain resolution. Carry identity, metadata, definitions, appearances, and relationships through replacement. Gate on a shaped typed Roof, nested rotated World geometry queries, and the public Placement scenarios above: bodyless frame queries, moves, both reparent policies, deletion dependencies, and atomic rejection. Retain invalid graph/ownership rejection. Replace the existing model once rather than maintaining parallel models. Related decisions: [ADR-0001](adr/0001-independent-product-representation-and-placement.md), [ADR-0002](adr/0002-authored-body-authority.md), [ADR-0004](adr/0004-document-resolved-placement-and-datum.md), [ADR-0008](adr/0008-explicit-bim-type-identity.md).
4. **Semantic and IFC convergence.** Introduce the shared facility/classification model and separate semantic handlers from representation/placement encoding. Preserve #2273/#2278 reconstruction and cleanup while completing item outcomes, shared aggregates, appearance, type identity, external classification associations, and diagnostics. Gate on supported schema/profile contracts, preserved type/property/classification graphs, independent validation of fresh output, negative semantic fixtures, diagnostic-free successful export, all-item partial failures, thin-panel reload, and the Building/Bridge/Road/Railway support matrix. The semantic acceptance cases above are required alongside geometry acceptance. Related decisions: [ADR-0006](adr/0006-ifc-exchange-adapter.md), [ADR-0007](adr/0007-ifc-import-fidelity-and-item-outcomes.md), [ADR-0008](adr/0008-explicit-bim-type-identity.md).
5. **Typed Families cutover.** Make the coordinated target-independent Families contract change, then delete display-name routing, whole-tree civil switching, and wrapper recovery. Gate on direct authored roof preservation, #2259/#2270 regressions, explicit unsupported typed intent, and Bodyless assembly projection. Nested-Site policy is implemented only after its legal hierarchy is separately settled. Related decisions: [ADR-0005](adr/0005-families-projection-into-bim.md).
6. **Extension probes and package release.** Add or rebase Sign and Member through the completed interfaces, inspect the diffs against the extension criterion in ADR-0001, then curate model/authoring/IFC/Families and focused standards entrypoints. Gate on packed ESM/CJS/declaration consumers, dependency-direction checks, affected repository suites, and self-contained consumer fixtures installed from the packed artifact. Independently qualify IFC bytes generated by those packed consumers and record checks in the receiving applications claimed by the release. Package-root model imports must not load IFC or Families transitively. Do not carry the old barrel through compatibility re-exports. Related decisions: [ADR-0001](adr/0001-independent-product-representation-and-placement.md), [ADR-0006](adr/0006-ifc-exchange-adapter.md).

Geometry and cleanup gates must run against the supported native backends, not only mocks or TypeScript compilation. Public-interface tests establish shape, ownership, and exchange behavior; focused injected failures cover cleanup paths. Issues reported by third-party projects motivate repository-owned regression fixtures; they do not replace verification of a newly built package.

## Non-goals and separate follow-up

- This documentation change does not implement the migration, update issue states, or authorize a release.
- No repository split, multiple BIM npm packages, full IFC-schema mirror, open runtime geometry registry, new writer backend, general constraint solver, or repository-wide owned/borrowed handle branding.
- Full grid/linear resolution, Road/Railway authoring, imported-to-authored normalization, per-item appearances, and configurable IFC units require separate scope. Preserve their intent/support states without claiming implementation.
- Support for the `IFC4X3_ADD2` schema alias is a focused reader/capability follow-up, motivated by reported import failures. It does not expand the neutral model. Configurable IFC output units remain a separate feature.
- The asymmetric Beam profile correction remains focused authoring geometry work. Foreign-object cleanup requires backend-specific ownership/declaration work and IFC runtime adaptation where needed. Circular tessellation requires a reduced reproduction before responsibility is assigned. Diagnostic-free successful export is an IFC adapter completion gate, not a reason to replace the backend.
- Exact nested-Site legality and root identity behavior require a focused hierarchy decision. Role-to-schema mapping needs its own review and must stay separate from physical element metadata and reusable type identity. The ADRs assign the owning modules without approving every proposed enum or hierarchy rule.
- Third-party adoption, project set-out, temporary hierarchy workarounds, Family definition packaging, grading tools, scaffold guidance, and source-data corrections are outside this architecture migration.
- Optional versus mandatory `web-ifc` and Families dependency declarations remain deferred until packed consumers establish the release constraints. The focused entrypoint direction is retained; exact export names and peer packaging do not block the document/Body design.

## Review still outstanding

Accepted package, Placement, identity, glossary, and explicit authored-authority rules remain in force. The eight records and this integrated migration sequence remain Proposed pending review; their creation does not accept the additional recommendations.

The IFC preservation amendments are also a review draft. They propose explicit type fallback policy, external classification retention, semantic import outcomes, and mandatory independent qualification. Applying this draft does not mark those policies accepted or implemented.

No unresolved consequential choice blocks the documentation split. Exact peer-dependency packaging, nested-Site legality and root identity behavior, detailed role-to-schema tables, and imported-document normalization remain separately scoped decisions. They do not reopen accepted rules. Exact interface names and optimization choices may change while preserving the contracts.

These are future implementation gates, not passing test results from this documentation change. Copies, generated realization, and temporary unions have unmeasured costs. This direction introduces no cache or promised performance gain.
